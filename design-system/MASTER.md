# Faro 设计规范 (MASTER)

来源：ui-ux-pro-max 的 AI-Native UI 风格 + 开发者工具配色，按 macOS 桌面应用取舍。
界面只引用本文件的语义令牌，不在组件里写死颜色。主题皮肤 = 另一套令牌，不改组件。

## 一、产品定位与设计立意

Faro 管的是"流量从哪里出去"。用户最在意的不是节点列表，而是三件事：
**现在每个服务从哪个出口走、有没有漏、出了问题能不能立刻断掉。**
所以界面围绕"出口车道（lane）"组织，而不是围绕节点表。

"聪明"的含义（不接大模型，全部是确定性的本地逻辑）：
1. **可解释**：任何一条连接都能回答"为什么走了这里"（命中哪一行规则、哪个节点）。
2. **环境感知**：守卫状态常驻显示（有没有漏、门是否关着），异常主动出现，平时安静。
3. **改之前先看差异**：规则点"应用"前显示新增/修改了哪几行，可一键撤销。
4. **不让人犯错**：规则写错带行号；严格路由没有节点时明确告知"将被阻断"；关熔断门之类的操作有清晰的状态文字。
5. **⌘K 命令面板**：跳转页面、切换节点、开关熔断门。纯本地，不联网。

不做：AI 助手 / 自然语言改规则 / 任何向外部服务发送用户配置的功能。
理由：代理的核心是稳定、不漏、可控；规则由用户自己写；外发路由习惯与生成不确定的规则都违背这个目标。

## 二、令牌

### 颜色（语义令牌，深浅各一套，对比度均已核对）

| 令牌 | 深色 | 浅色 | 用途 |
|---|---|---|---|
| bg | #0F172A | #F8FAFC | 窗口底 |
| surface | #1B2336 | #FFFFFF | 卡片 |
| surface-2 | #272F42 | #F1F5F9 | 悬停、输入框底、分段控件 |
| border | #FFFFFF 12% | #0F172A 10% | 1px 细边，不用实线灰 |
| text | #F8FAFC | #0F172A | 正文 |
| text-2 | #94A3B8 | #475569 | 次要文字（≥4.5:1） |
| accent | #3B82F6 | #2563EB | 品牌色：选中项、主按钮、打开的开关（灯塔的天蓝） |
| ok | #34D399 | #15803D | 正常：运行中、快速的出口。绿色只表示"没问题"，不是品牌色 |
| on-accent | #FFFFFF | #FFFFFF | accent 上的文字 |
| danger | #EF4444 | #DC2626 | 门已关、拒绝、错误 |
| warn | #F59E0B | #B45309 | 提醒、降级 |
| info | #38BDF8 | #0369A1 | 链接、规则差异里的新增行 |

规则：颜色从不单独表达含义，状态一律 图标 + 文字 + 颜色（门关着写"已切断"，不只是变红）。
车道区分用 5 个低饱和色相做左侧细条，旁边始终有名字。

### 字体与字号
- 界面字体：系统字体（SF Pro）。skill 推荐 Inter，但系统字体与 Inter 同类、无需打包，符合"内存极致"。
- 数据字体：SF Mono，**等宽数字**（延迟、速度、端口、域名），数字变化时不抖动。
- 字号阶梯：11 角标 / 12 辅助 / 13 正文 / 15 小标题 / 20 页标题 / 28 关键数字。
- 字重：400 正文，500 标签，600 标题。行高正文 1.5，数据行 1.35。

### 间距、圆角、层级
- 间距 4/8 递进：4, 8, 12, 16, 24, 32。
- 圆角：控件 8，卡片 12，药丸 999。
- 层级：只有三层（bg < surface < 浮层），浮层才有阴影；卡片靠 1px 边，不靠阴影。
- 控件最小高度 32；可点区域不小于 32×32（桌面指针，不套用触屏 44）。

### 动效
- 150–250ms，ease-out 进、更快退（约 60%）；位移只用 transform/opacity。
- 只在"有因果"时动：门开合滑动、延迟条变化、规则差异出现、状态点脉冲。
- 尊重"减少动态效果"：关闭脉冲与流式，直接显示结果。
- 任何动画可被打断，不阻塞输入。

- 导航项：图标 + 文字，当前项高亮；顺序固定，所有页面一致。

- 命令面板在内容区顶部右侧，⌘K 唤起，不占页面。

## 四、页面

1. **现在**（首页）：出口车道 + 实时流量 + 守卫。
   车道 = 一行：`[服务/规则来源] → [闸门] → [出口节点 · 延迟 · IPv4]`，右侧小折线显示该车道流量。
   点车道展开节点选择；闸门是一个带文字的开关（"放行 / 已切断"）。
2. **订阅**：每订阅一张卡片：名称、用量进度条、到期、节点数、更新、删除。添加入口在顶部（链接或文件）。
3. **连接**：实时表格。每行：主机、进程、命中规则行、出口、上下行。行内"为什么？"展开解释链。可搜索、可断开。
4. **规则**：顶部切换"我的域名 | 规则文本"。"我的域名"是日常用的：按分组存，每组一个名字、一个去向、一批域名，改去向整组一起换，组的顺序就是优先级，排在规则文本前面；连接页点开一条连接可一键加入分组。"规则文本"是原来的编辑器加生成的配置。没有内置预设，规则都是用户自己写的。
5. **日志**：级别过滤、搜索、暂停；暂停时保留缓冲。
6. **设置**：系统代理、端口、开机自启、规则集更新、核心版本、外观。

空状态必须给出下一步（"粘贴订阅链接以开始"），不留空白。加载超过 300ms 用骨架，不用转圈挂住界面。

## 五、命令面板与解释

- ⌘K 打开，输入即过滤，回车执行。条目：页面跳转、"切换 <路由> 的节点"、"切断/放行 <路由>"、启停、开关系统代理。
- 只匹配本地条目（路由名、节点名、页面名），不联网，不做自然语言理解。
- 连接页的"为什么？"：由规则引擎对该连接重新求值，列出依次检查过的规则，标出命中的那一行和最终出口。
- 守卫：对每个带"期望出口"的路由，核对实际连接的出口；不符就在侧栏守卫处变为警告并给出连接详情。

## 六、与代码架构的对应

```
internal/engine/   订阅、规则编译、配置生成、核心进程、连接追踪（无界面）
internal/api/      对外接口：Go 接口 + 本机受密钥保护的控制接口（读状态、切节点、开关熔断门）
ui/                theme.go（令牌）、shell.go（侧栏+命令面板）、pages/*.go
internal/presets/  只有一份中性的起始规则（base）；任何具体服务的规则由用户自己写，程序和随包数据里都不出现服务名
```


## 七、品牌与资源（Faro）

- 名称：Faro，西班牙语"灯塔"。标识是灯塔向两侧各投一束光（天蓝、靛蓝），深色圆角底。
- 应用图标：`resources/icon.png`（1024，四角透明）；源文件 `ui_assets/faro-logo.svg`。
- 菜单栏图标：`resources/tray.png`，模板图（黑色加透明，系统按菜单栏深浅自动着色），由 `go run ./cmd/genicon` 生成。18pt 下只保留塔身、灯和两道光弧，更多细节会糊。
- 侧栏顶部：Logo 36pt（带 1px 细边，深色侧栏上保持轮廓）、名称、版本号。
- 选中的导航项用品牌色实心填充加白字加字重变化（不只靠颜色）；侧栏"现在"旁的圆点表示有熔断门关着。
- 规则页的"生成的配置"面板：始终深色，键橙色、字符串绿色、数字蓝色；不含服务器、端口、密钥、控制器密码。
- 设计参考图：`file/` 下的 Gemini 图。取其：实心选中、更大圆角、配置预览面板；暂不取：顶部"规则/全局/直连"模式切换（见下）、TUN 开关。

### 待定
- **模式切换（规则 / 全局 / 直连）**：核心支持，但"直连"会绕过严格路由和熔断门，把本该固定出口的账号流量直接放出去。需要先定语义：直连是否仍遵守阻断和熔断。
